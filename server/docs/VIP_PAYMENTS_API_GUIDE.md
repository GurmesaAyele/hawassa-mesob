# Hawassa MESOB VIP Tickets — Chapa Payment Integration API Guide

This guide documents the Chapa v2 payment integration for Hawassa MESOB VIP ticket applications.

---

## 1. Overview & Payment Lifecycle

The VIP payment integration follows an authoritative, server-verified lifecycle:

```
[Citizen Submits Application]
              │
              ▼
   POST /api/vip-tickets (Status: PENDING)
              │
              ▼
   POST /api/vip-payments/initialize
              │
              ├── Returns Chapa Hosted Checkout URL
              ▼
[Citizen Redirected to Chapa Hosted Checkout]
              │
              ├── Completes Payment on Chapa
              ▼
[Citizen Redirects back to Frontend Return URL]
              │
              ▼
[Frontend Displays Processing Screen]
              │
              ▼
   GET /api/vip-payments/status/:reference  (Polling loop)
              ▲
              │ (Simultaneously, Webhook or Server Verification completes)
              ▼
   Ticket status transitions: PENDING ➔ CONFIRMED
              │
              ▼
[Frontend Displays VIP Confirmation with Reference]
              │
              ▼
[Citizen physically arrives at Hawassa MESOB Center]
              │
              ▼
   POST /api/vip-tickets/:id/enqueue ➔ Walk-In Queue Assignment (e.g. VIP-001)
```

---

## 2. Business & Security Rules

1. **Fixed Fee**: The VIP fee is strictly **1,000 ETB** per application, regardless of the number of services selected.
2. **Amount Representation**: In Chapa v2, amounts are calculated in integer minor units (cents): `100000` = 1,000 ETB. The fee is calculated authoritatively on the server.
3. **Reference Separation**:
   - **Application Reference (`reference`)**: Generated by MESOB, e.g., `VIP-845123-A4B2`.
   - **Merchant Reference (`merchantReference`)**: Generated internally for Chapa (strictly $\le 20$ chars, uppercase alphanumeric), e.g., `VP7A2F8B12C3D4E5`.
   - **Provider Reference (`providerReference`)**: Returned by Chapa upon checkout initialization/completion.
4. **Authoritative Server Verification**: The frontend must **never** trust browser redirect query parameters (`?status=success`) as proof of payment. Only the backend verification against Chapa's official API marks a ticket as `CONFIRMED`.
5. **Separation of Concerns**:
   - `vip_tickets.status`: Application lifecycle (`PENDING` ➔ `CONFIRMED` ➔ `QUEUED` ➔ `SERVING` ➔ `USED` / `CANCELLED`).
   - `vip_payments.status`: Provider payment transaction state (`PENDING` ➔ `SUCCESS` / `FAILED` / `CANCELLED` / `EXPIRED`).
   - Queue assignment happens only during physical check-in (`POST /api/vip-tickets/:id/enqueue`).

## 3. Endpoints

### 3.1 Initialize Payment
Start a Chapa hosted checkout session for an existing VIP application.

* **URL**: `/api/vip-payments/initialize`
* **Method**: `POST`
* **Headers**: `Content-Type: application/json`

#### Request Body
```json
{
  "reference": "VIP-845123-A4B2",
  "returnUrl": "http://localhost:5173/vip/payment/callback"
}
```

#### Success Response (`201 Created` or `200 OK` for re-used active session)
```json
{
  "success": true,
  "message": "Chapa hosted checkout session initialized successfully.",
  "data": {
    "applicationReference": "VIP-845123-A4B2",
    "merchantReference": "VP7A2F8B12C3D4E5",
    "checkoutUrl": "https://checkout.chapa.co/checkout/payment/...",
    "amount": 100000,
    "currency": "ETB",
    "status": "PENDING"
  }
}
```

#### Error Responses
* `400 Bad Request`: Missing `reference` or invalid parameters.
* `404 Not Found`: VIP application does not exist.
* `409 Conflict`: Application already confirmed/paid, or active in queue.
* `502 Bad Gateway`: Chapa provider initialization failure.

---

### 3.2 Poll Payment Status
Used by the frontend to display real-time payment progression without triggering redundant external API requests.

* **URL**: `/api/vip-payments/status/:reference`
* **Method**: `GET`
* **Path Parameter**: `:reference` — Can be the VIP application reference (`VIP-845123-A4B2`) or the Chapa merchant reference (`VP7A2F8B12C3D4E5`).

#### Success Response (`200 OK`)
```json
{
  "success": true,
  "data": {
    "applicationReference": "VIP-845123-A4B2",
    "merchantReference": "VP7A2F8B12C3D4E5",
    "providerReference": "chapa-ref-987654",
    "paymentStatus": "SUCCESS",
    "ticketStatus": "CONFIRMED",
    "amount": 100000,
    "currency": "ETB",
    "paymentMethod": "telebirr",
    "checkoutUrl": "https://checkout.chapa.co/...",
    "isVerified": true,
    "updatedAt": "2026-10-25T14:30:00.000Z"
  }
}
```

---

### 3.3 Authoritative Payment Verification
Explicitly triggers a server-to-server check with Chapa v2 to verify and confirm payment.

* **URL**: `/api/vip-payments/verify/:reference`
* **Method**: `GET`
* **Path Parameter**: `:reference` — Merchant reference or provider reference.

#### Success Response (`200 OK`)
```json
{
  "success": true,
  "message": "Payment successfully verified. VIP application is now CONFIRMED.",
  "data": {
    "applicationReference": "VIP-845123-A4B2",
    "merchantReference": "VP7A2F8B12C3D4E5",
    "providerReference": "chapa-ref-987654",
    "paymentStatus": "SUCCESS",
    "ticketStatus": "CONFIRMED",
    "amount": 100000,
    "currency": "ETB",
    "paymentMethod": "telebirr",
    "verifiedAt": "2026-10-25T14:30:00.000Z"
  }
}
```

---

### 3.4 Webhook Notification
Endpoint registered with Chapa to receive asynchronous payment event notifications.

* **URL**: `/api/vip-payments/webhook`
* **Method**: `POST`
* **Headers**: `x-chapa-signature: <hmac-sha256-hex>`
* **Authentication**: Automated HMAC-SHA256 signature verification over exact raw request body.

## 4. Frontend Integration Checklist

1. **Submit VIP Application**: Call `POST /api/vip-tickets` to obtain the application reference (`ticketCode`).
2. **Initialize Checkout**: Call `POST /api/vip-payments/initialize` with the reference.
3. **Redirect Customer**: Redirect customer window to the returned `checkoutUrl`.
4. **Return Callback**:
   - Customer is redirected by Chapa to `CHAPA_RETURN_URL`.
   - Do **not** assume payment succeeded from URL parameters alone.
   - Show a loading spinner: *"Confirming your VIP payment with Hawassa MESOB..."*
   - Call `GET /api/vip-payments/status/:reference` or `GET /api/vip-payments/verify/:reference`.
   - Poll every 3 seconds (up to 10 attempts / 30 seconds).
5. **Success State**:
   - When `data.paymentStatus === "SUCCESS"` and `data.ticketStatus === "CONFIRMED"`, show the confirmation screen.
   - Remind citizen: *"Your application is confirmed! When you arrive at Hawassa MESOB Center, check in at the reception or kiosk to enter the priority walk-in queue."*
